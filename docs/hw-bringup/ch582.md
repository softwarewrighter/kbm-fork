# Bring-up plan: WCH CH582F (bare metal)

The CH582F is a WCH QingKe **RISC-V4A** core: RV32IMAC, no FPU, run at
60 MHz here. It has **32 KB SRAM**, 448 KB code flash, BLE 5.3 and native
USB. This is the smallest target k has been fitted to.

Goal: k's REPL on UART1, passing `test/golden/basic.k`. `big.k` needs
≥ 256 KiB of heap, which the chip does not have, so it is skipped.

## How k fits in 32 KB

| | Size | Notes |
|---|---|---|
| k's heap | 16 KiB | `KHEAP=8`; `KHEAP=7` gives 8 KiB, which also passes basic.k |
| handle table | 2 KiB | `KOBJ=8`: 256 objects |
| k's other statics + SDK | ~3 KiB | |
| stack | 8 KiB | reserved at the top of RAM by WCH's linker script |
| **total** | **29 KB of 32** | the link fails if it does not fit |
| flash | 111 KB of 448 | k compiled with GCC `-Os` |

k's stack peaked at about **3.7 KiB** across the golden scripts with GCC
`-Os`. This was measured in QEMU by painting the stack. **Do not build k with
GCC `-Ofast` here.** GCC then inlines k's 64-byte generic vectors into a
6 KB stack frame, and `1+2` needs 8.9 KiB of stack: it overflows the 8 KiB
stack and hangs. clang `-Ofast` needs about 3.5 KiB.
This k edition has no lambdas and
rejects nested parentheses, so recursion depth stays small.

**No BLE while k runs.** WCH's BLE stack needs RAM that k is using. Running
both would mean shrinking k's heap to 8 KiB (`KHEAP=7`) and testing it. That
is out of scope.

## What is ready (verified here)

- **`boards/ch582/`:** builds `k-ch582.{elf,bin,hex}` with Debian's
  `riscv64-unknown-elf-gcc` 13.2 against WCH's EVT SDK
  (github.com/openwch/ch583, Apache-2.0, pinned to commit `bd508ad`). The
  build script fetches the SDK itself.
  - Startup code, linker script, and the clock/GPIO/UART1 drivers are
    WCH's.
  - The whole board port is `con_ch58x.c`: 40 lines of polled UART1.
- **QEMU stand-in:** `boards/mcu/build.sh --test` target
  `rv32imac-ch582-virt-gccsrc`. It is the same GCC with the same k flags
  (`-Os`), heap, handle table and 8 KiB stack, on QEMU riscv32 `virt`. It
  passes `basic.k`, prints `wsfull` for `test/limits/heap.k`, and fits a
  32 KB RAM budget.

Not verified: anything on the chip itself (no emulator exists for it),
WCH's startup code and clock driver as built by stock GCC, the UART pins on
your particular board, and `\t`.

## Prerequisites (bring-up machine)

- `gcc-riscv64-unknown-elf` and `libnewlib-dev` (Debian/Ubuntu). Debian's
  bare GCC has no libc headers, and the SDK needs `<string.h>`.
  Alternatively use an xPack `riscv-none-elf-gcc`:
  `CC=riscv-none-elf-gcc boards/ch582/build.sh`.
- **wchisp**, WCH's USB ISP protocol in Rust:
  `cargo install wchisp --git https://github.com/ch32-rs/wchisp`
  (needs libusb: `apt install libusb-1.0-0-dev`). On Linux, give the user
  access to WCH's ISP device, or run wchisp with sudo the first time; the
  ISP device is usually USB ID 4348:55e0 (`lsusb`). WCH's Windows
  WCHISPTool also works.
- A **3.3 V USB-serial adapter** for k's console. These boards usually have
  only the chip's native USB, with no USB-UART bridge. Wire it to:
  - **PA9 = TXD1** (board TX → adapter RX)
  - **PA8 = RXD1** (adapter TX → board RX)
  - GND
  
  Use 115200 8N1. Never use a 5 V adapter.
- Python 3 with `pyserial` for `test/drive_serial.py`.

## Safety (read first)

- **Allowed:** `wchisp flash <file>` (it erases and writes the code flash)
  and `wchisp info`. These are routine and recoverable, because the ISP
  bootloader lives in its own protected area. If the board seems dead,
  hold BOOT while plugging in USB.
- **Never, without the human's approval:** `wchisp config` writes
  (`config set` / `config reset`), or anything that changes option bytes
  or code/debug protection. A bad config can disable the BOOT-pin
  bootloader or 2-wire debug. Recovery then needs a WCH-Link on PB14/PB15,
  or worse.
- Work on branch `hw/ch582` off `spike/portable-k`; commit and push results.

## Steps

### 1. Build

```sh
boards/ch582/build.sh         # first run clones the EVT SDK into boards/ch582/.evt
```

Expect `flash=111 KB of 448  RAM=29 KB of 32`. Optional pre-check of k
itself in QEMU: `boards/mcu/build.sh --test`, then look for the
`rv32imac-ch582-virt-gccsrc` line.

### 2. Flash

1. Enter ISP mode: hold **BOOT**, plug in the board's USB-C, then release
   BOOT. `lsusb` should show the WCH ISP device.
2. Check the chip: `wchisp info`. It must report a CH582. If it reports
   another CH58x/CH57x, stop: the RAM budget and linker script assume a
   CH582.
3. Flash: `wchisp flash boards/ch582/build/k-ch582.bin`. The ELF or HEX
   also works.
4. Reset: press RST, or unplug and replug **without** BOOT held.

The ISP bootloader stays in ISP mode only briefly. If wchisp cannot find the
device, re-enter ISP mode and run the command straight away.

### 3. Smoke test

```sh
python3 -m serial.tools.miniterm /dev/ttyUSB0 115200   # the adapter's port; Ctrl-] quits
```

Press RST. The banner `... (c)arthur whitney(l)MIT` appears, then type:
- `1+2` → `3`
- `3^!10` → rows `0 1 2`, `3 4 5`, `6 7 8`
- `\\` → the chip resets back into k

### 4. Acceptance

```sh
python3 test/drive_serial.py test/golden/basic.k /dev/ttyUSB0 | diff test/golden/basic.expected -
```

Start the command, then press RST within 60 s. The adapter's RTS is not
wired to RST, so `--reset` does nothing here. If k is already at its
prompt, use `--attached` instead.

Heap limit: `python3 test/drive_serial.py --attached test/limits/heap.k /dev/ttyUSB0 | tail -2`
should print `wsfull`, and then the chip resets (expected).

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| No banner | TX/RX swapped, wrong port, or the board routes UART1 elsewhere. Check the board's silkscreen for TX1/RX1. Try the UART1 example in `.evt/EVT/EXAM/UART1` built the same way. |
| Garbage characters | Clock or baud mismatch. `con_ch58x.c` uses `CLK_SOURCE_PLL_60MHz` and `UART1_DefInit` (115200 at `FREQ_SYS` 60 MHz). |
| Hangs or resets on `\t` | The `rdcycle` CSR is unimplemented on this core and traps (the weak HardFault handler spins). Replace `ut` for this target in `ksrc/ksys.h` with a SysTick read, and record the change here. |
| `wsfull` early | The heap is 16 KiB by design. Keep scripts small, or `KHEAP=7` if RAM is needed elsewhere. |

## Possible later step: console over native USB

WCH's EVT has a USB CDC device example (`EVT/EXAM/USB`). Wiring
`con_getc`/`con_putc` to it would remove the external adapter. That uses
WCH's USB stack, so no driver has to be written, but it costs RAM that k
is using. Measure it before committing to it.
